Никаких push, merge, squash, rebase-merge или auto-merge в `main` без отдельной прямой команды Ильи. Готовый прототип, успешные тесты и просьба «продолжай работу» сами по себе такого разрешения не дают.

Текущая явно разрешённая пользователем ветка — `prototype/0.2` (от canonical main). Ранее использовалась `prototype/0.1`; далее — только согласованные рабочие ветки. Пушить только рабочие ветки. Без force-push, `push --all`, `push --mirror`, обхода защиты и изменения видимости репозитория. При существующей main — draft PR для проверки, без merge. Если main отсутствует, не создавать её самостоятельно; первый push только в prototype/0.1.

Целевой репозиторий: https://github.com/IliaMerkurev/RockSnakePlayableTest . Он должен быть приватным. Проверить адрес origin, текущую ветку и isPrivate перед первым push. На момент подготовки пакета создание репозитория не подтверждено.

## Текущая задача

Исходное ТЗ: `DOTS_TASK_v0.1.md`; актуальные явно утверждённые изменения v0.2: `docs/RULES_V02.md`, они заменяют противоречащие правила v0.1. Чеклист: `docs/ACCEPTANCE_CHECKLIST.md`.

Нужен играбельный прототип на VM dots, открытый в браузере для личной проверки пользователем. Не сдавать только исходники, скриншоты или видео.

Чистый Three.js + TypeScript + Vite; HTML/CSS UI; Pointer Events; Vitest/Playwright только для разработки. Не использовать дополнительный игровой движок, React/R3F, физику или WebGPU. Зависимости закрепить в lockfile.

Вся графика v0.1 — программные примитивы. Стены из боксов, камни жёсткие и low-poly, одна геометрия нейтрального работника с отдельной каской. Уровни отличаются только цветом каски и отдельной цифрой уровня. Не создавать зомби и не ждать генерации моделей.

Основной цикл: конвейер/бочки → работники → размещение/merge → добыча камней → монеты → покупка площадок. Также бонусные монеты и бомба. Это реальная логика, не записанная последовательность.

Мышь и touch равноправны. Обязательны отмена drag, pointer capture, корректные hit-зоны и отсутствие дублирования команд. Объекты и деньги не должны исчезать/удваиваться при невалидных действиях.

Экспорт — один автономный `dist/playable/index.html`. Цель v0.1 ≤2 000 000 байт, жёсткий предел <5 000 000 байт. Без CDN/remote assets, runtime API, аналитики, видео, шрифтов из сети и debug-читов. Рекламные SDK пока заменены безопасным браузерным адаптером, не считать его готовой интеграцией.

Все настройки экономики/камеры/ввода — в понятном конфиге. Логика состояния отделена от мешей, чтобы позже заменить визуал.

## Перед сдачей

По новому указанию пользователя проверять только новые и непосредственно затронутые сценарии, не повторять уже проверенные полные suites; запускать typecheck/focused unit/build/budget и bounded QA нового поведения; вручную пройти цикл; проверить standalone HTML без дополнительных запросов. Оставить сервер работающим, открыть игру, сообщить фактическую ссылку VM/preview. Привести ветку, удалённый SHA, размер HTML в байтах, результаты и ограничения тестирования.

Не выдумывать успешные команды, тесты, создание репозитория, push, доступный preview и испытания на физических телефонах. Ошибки доступа или VM сообщать прямо. Если push заблокирован, сохранить локальные изменения и указать блокер.

После сдачи v0.1 остановиться для обратной связи. Не начинать генерацию моделей и не мерджить в main без отдельного указания.
